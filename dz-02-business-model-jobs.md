# ДЗ-2. Бизнес-модель и работы пользователя

## Бизнес-модель B2C-варианта

| Блок | Ответ |
|---|---|
| Сегменты — для кого | Частный владелец нескольких квартир, например пяти квартир в Санкт-Петербурге, который самостоятельно начинает сдавать их посуточно и устанавливает цены без команды. |
| Ценностное предложение — какую работу выполняем лучше | Помогаем назначить обоснованную цену за ночь для каждой квартиры и даты: после ввода параметров сразу показываем рекомендацию, которую можно принять или изменить. Вместо ручного просмотра похожих объявлений владелец получает отправную точку в процессе размещения. |
| Каналы — как доходим до пользователя | Поиск по запросам о посуточной аренде и цене квартиры, статьи и видео для собственников, рекомендации пользователей. Эти каналы предстоит проверить на первых клиентах. |
| Отношения с клиентами — разовая сделка или подписка | Самостоятельное подключение через приложение, пробный расчёт, затем месячная подписка; поддержка через чат или электронную почту. |
| Источники дохода — за что платят | Владелец платит из личных средств за доступ к рекомендациям цен для своих квартир и выбранных дат. Тариф ограничен числом активных квартир. |
| Ключевые ресурсы — данные, модель, инфраструктура | Разрешённые к использованию данные об объектах и ценах, обученная модель, каталог квартир, сервер и интерфейс приложения. |
| Ключевые процессы — что делаем сами | Получаем и проверяем данные, обучаем и оцениваем модель, выдаём рекомендацию при создании объявления, поддерживаем приложение и обновляем модель. |
| Партнёры — кто делает часть работы | Поставщики инфраструктуры и платёжный провайдер; потенциально — владельцы или площадки, которые разрешат использовать данные для обучения. 
| Структура затрат — во что обходится | Разработка и поддержка приложения, хранение данных, вычисления для обучения и выдачи рекомендаций, платёжные комиссии, привлечение пользователей. |

## Бизнес-модель B2B-варианта

| Блок | Ответ |
|---|---|
| Сегменты — для кого | Управляющие компании, которые ведут десятки квартир для посуточной аренды; непосредственный пользователь — риелтор, решение о покупке принимает операционный директор. |
| Ценностное предложение — какую работу выполняем лучше | Помогаем массово пересчитать цены по объектам и датам перед сезоном: риелтор загружает портфель, получает рекомендации и выгружает тарифы для команды. Это заменяет поштучной ручной расчёт для каждой квартиры. |
| Каналы — как доходим до пользователя | Прямые обращения к управляющим компаниям, демонстрация на их портфеле, профессиональные сообщества управляющих посуточной недвижимостью. |
| Отношения с клиентами — разовая сделка или подписка | Корпоративная подписка с демонстрацией, настройкой загрузки объектов и поддержкой сотрудников. |
| Источники дохода — за что платят | Компания платит из бюджета управления объектами ежемесячно за число активных квартир, для которых доступны массовые рекомендации и выгрузка тарифов. |
| Ключевые ресурсы — данные, модель, инфраструктура | Та же модель и разрешённые рыночные данные, плюс данные портфеля клиента, пакетный расчёт, разграничение доступа сотрудников и инфраструктура выгрузки. Данные клиентов используются для обучения только при отдельном разрешении. |
| Ключевые процессы — что делаем сами | Подключаем и проверяем портфель, выполняем массовый расчёт, формируем выгрузку, отслеживаем качество рекомендаций и поддерживаем корпоративных клиентов. |
| Партнёры — кто делает часть работы | Поставщики инфраструктуры и платёжный провайдер; потенциально — поставщики рыночных данных и системы управления объектами для импорта и экспорта. Интеграции и соглашения пока не подтверждены. |
| Структура затрат — во что обходится | Разработка пакетной обработки и выгрузки, вычисления, хранение данных, внедрение и поддержка клиентов, продажи, возможная стоимость прав на данные. |

## Три работы пользователя

### Работа 1 — назначить стартовую цену для квартиры (B2C)

| Элемент | Ответ                                                                                                                                                                                                                               |
|---|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Когда:** контекст — особенности человека и ситуации | Частный владелец освобождает первую из пяти квартир после долгосрочной аренды и собирается впервые разместить её для посуточной сдачи. Опыта ценообразования по ночам у него нет.                                                   |
| **Когда:** негативные эмоции — что чувствует, пока результата нет | Боится поставить цену слишком низко и недополучить доход либо слишком высоко и остаться без заявок.                                                                                                                                 |
| **Когда:** известные решения — что уже знает о способах | Может вручную посмотреть похожие объявления или спросить знакомого риелтора; понимает, что объявления не всегда сопоставимы по площади, расположению и датам.                                                                       |
| **Когда:** триггер — событие, запускающее действие | Квартира освободилась; владелец создаёт первое объявление и должен указать цену за ночь.                                                                                                                                            |
| **Хочу:** ожидаемый результат — «хочу + глагол» | Хочу назначить стартовую цену за ночь для этой квартиры.                                                                                                                                                                            |
| **Хочу:** критерии успеха — по чему судит, что вышло | Цену можно указать до публикации объявления; на выбор цены уходит не более 10 минут вместо примерно 30 минут ручного просмотра аналогов. После первых 10 заявок владелец проверит, пришлось ли менять стартовую ставку более чем на 15%. |
| **Хочу:** процесс перехода — что для этого делает | Вводит параметры квартиры и даты, смотрит предложенную цену и решает, оставить её или изменить.                                                                                                                                     |
| **Чтобы:** работа более высокого уровня — ради чего всё это | Чтобы запустить посуточную сдачу квартиры с понятной для себя ставкой и не откладывать публикацию объявления.                                                                                                                       |

**Одной фразой:** Когда квартира освободилась и я создаю первое объявление, я хочу назначить стартовую цену за ночь не более чем за 10 минут вместо примерно 30 минут ручного поиска, чтобы начать посуточную сдачу.

### Работа 2 — скорректировать цену на праздничные даты (B2C)

| Элемент | Ответ |
|---|---|
| **Когда:** контекст | Тот же владелец уже сдаёт пять квартир посуточно; обычные цены указаны, но впереди праздничные выходные. |
| **Когда:** негативные эмоции | Переживает, что оставит будничную ставку и недополучит доход либо поднимет её слишком сильно. |
| **Когда:** известные решения | Может вручную сравнить объявления на те же даты или оставить текущую цену; сравнение всех пяти квартир занимает время. |
| **Когда:** триггер | Открываются даты бронирования на ближайшие праздничные выходные. |
| **Хочу:** ожидаемый результат | Хочу скорректировать цену на праздничные даты для своих квартир. |
| **Хочу:** критерии успеха | Для всех пяти квартир цены на выбранные даты выставлены до начала приёма заявок; на это уходит не более 20 минут вместо примерно часа ручного сравнения пяти объектов. По итогам праздников владелец может сопоставить выручку и занятость с обычными выходными. |
| **Хочу:** процесс перехода | Выбирает праздничные даты, просматривает рекомендации по пяти квартирам и утверждает или меняет предложенные ставки. |
| **Чтобы:** работа более высокого уровня | Чтобы подготовить квартиры к периоду повышенного спроса и самому контролировать доход. |

**Одной фразой:** Когда открываются праздничные даты, я хочу скорректировать цены для пяти квартир не более чем за 20 минут вместо примерно часа ручного сравнения, чтобы подготовиться к повышенному спросу.

### Работа 3 — пересчитать тарифы портфеля перед сезоном (B2B)

| Элемент | Ответ |
|---|---|
| **Когда:** контекст | Риелтор управляющей компании отвечает за тарифы примерно 40 посуточных квартир в Санкт-Петербурге; цены по датам нужно передать команде до начала летнего сезона. |
| **Когда:** негативные эмоции | Опасается пропустить объект или дату при ручном пересчёте и задержать подготовку тарифов. |
| **Когда:** известные решения | Сейчас может вести таблицу с объектами и вручную проверять похожие объявления; знает, что есть системы управления объектами, но в них тоже нужно загрузить готовые цены. |
| **Когда:** триггер | Операционный директор назначает срок подготовки тарифов на летний сезон. |
| **Хочу:** ожидаемый результат | Хочу пересчитать тарифы для портфеля квартир на предстоящий сезон. |
| **Хочу:** критерии успеха | Для всех 40 квартир есть рекомендованные цены по заданным датам и список объектов, где расчёт не удался; результат подготовлен за один рабочий день вместо нескольких дней поштучного ручного расчёта. Риелтор может выгрузить тарифы в таблицу для проверки директором. |
| **Хочу:** процесс перехода | Загружает список квартир и период, проверяет ошибки входных данных, просматривает рекомендации и выгружает тарифы. |
| **Чтобы:** работа более высокого уровня | Чтобы вовремя передать согласованный прайс команде и открыть продажи на сезон. |

**Одной фразой:** Когда директор ставит срок подготовки летних тарифов, я хочу пересчитать цены для 40 квартир за один рабочий день вместо нескольких дней ручной работы, чтобы команда вовремя открыла продажи на сезон.

## Сверка

В B2C владелец платит за рекомендации именно тогда, когда ему нужно назначить или скорректировать цены своих квартир (работы 1 и 2). В B2B компания платит за массовый расчёт и выгрузку тарифов — результат работы риелтора перед сезоном (работа 3). Доход не привязан к бронированиям гостей или рекламе: это не те результаты, ради которых описанные пользователи обращаются к продукту.
